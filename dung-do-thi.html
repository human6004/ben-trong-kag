Dựng đồ thị luật Việt Nam

Từ lúc chưa có gì chạy tới lúc hỏi được câu đầu tiên. Chín bước, mỗi bước có lệnh chạy và dấu hiệu để biết nó đã xong đúng.

01

Hai luật bất di bất dịch

Hai luật này không phải mẹo cho gọn, mà là hai lỗi làm hỏng cả buổi chạy. Vi phạm luật nào cũng hỏng ngay ở lệnh đầu tiên, trước cả khi tốn lượt gọi mô hình nào.

Luật một

Luôn đứng trong thư mục kag/. Đứng ở thư mục gốc project hỏng ngay vì hai lý do độc lập. Thư mục kag/ của project không có __init__.py nên Python cướp luôn tên gói kag và che mất thư viện thật. Và KAG tìm kag_config.yaml bằng cách đi ngược lên cây thư mục, đứng ở gốc thì file config là con chứ không phải tổ tiên, dò lên tận ổ đĩa vẫn không thấy.

Luật hai

Luôn gọi Python trong .venv. Lệnh python trên PATH là bản msys2 3.14 không có KAG. Bản đúng nằm ở .venv/Scripts/python.exe.

Bốn con số dưới đây là những gì cần biết trước khi bắt tay vào, để biết mình đang ở đâu và sắp tốn cái gì.

02

Chín bước

Chín bước nối tiếp nhau, đọc từ trên xuống. Chỉ hai bước cuối trong nhóm tốn tiền gọi mô hình, và bước 7 là chốt chặn nằm đúng giữa: qua được nó rồi mới nên chạy nốt 22 file còn lại.

Bước 1 · Dựng hạ tầng bằng Docker không gọi mô hình

Chạy ở: thư mục gốc project. Vì sao: bốn dịch vụ — OpenSPG server giữ schema và điều phối, Neo4j giữ đồ thị, MySQL giữ siêu dữ liệu project, MinIO giữ file. Lần đầu phải tải ảnh về nên lâu, các lần sau vài giây.

docker compose -f docker/docker-compose-west.yml up -d
Đúng thì thấy
release-openspg-server Up release-openspg-neo4j Up release-openspg-mysql Up release-openspg-minio Up

Kiểm bằng docker ps --format "{{.Names}}\t{{.Status}}".

Cảnh báo

Neo4j xin 4 GB heap, máy dưới 8 GB RAM sẽ ì. Container Neo4j cứ khởi động lại thì hạ NEO4J_server_memory_heap_max__size trong file compose xuống 2G.

Bước 2 · Chờ server thật sự sống không gọi mô hình

Vì sao: container “Up” không có nghĩa ứng dụng Java bên trong đã nạp xong. Bước sau báo lỗi kết nối nếu vội. Thường mất thêm một tới hai phút.

curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8887
# mở luôn Neo4j browser http://localhost:7474, user neo4j, mật khẩu neo4j@openspg
Đúng thì thấy
200

Còn 000 hoặc 502 thì chờ tiếp, xem docker logs --tail 20 release-openspg-server.

Bước 3 · Điền hai khoá API không gọi mô hình

Vì sao: mở kag/kag_config.yaml, thay cả ba chỗ api_key: key. Hai khối openie_llm và chat_llm dùng khoá DashScope của Alibaba. Khối vectorize_model dùng khoá SiliconFlow. Đây là việc phải tự làm, không ai làm thay được.

grep -n "api_key" kag/kag_config.yaml
Đúng thì thấy
4: api_key: sk-... 11: api_key: sk-... 17: api_key: sk-...
Cảnh báo

Đừng commit file này sau khi điền khoá. .gitignore chỉ chặn *.env và *.key, không chặn kag_config.yaml.

Bước 4 · Tạo project trên server không gọi mô hình

Chạy ở: kag/. Vì sao: lệnh tìm project tên Legal, không có thì tạo mới, rồi tự ghi số id ngược lại vào kag_config.yaml. Dùng restore chứ không phải create, vì create dựng thêm cả bộ khung thư mục mà project đã có rồi.

cd kag
../.venv/Scripts/knext.exe project restore --host_addr http://127.0.0.1:8887 --proj_path .
Đúng thì thấy
grep -n " id:" kag_config.yaml  →  dòng 31 có id khác rỗng, ví dụ id: '4'

Số cụ thể bao nhiêu không quan trọng, miễn khác rỗng.

Bước 5 · Đẩy schema lên server không gọi mô hình

Chạy ở: kag/. Vì sao: mười kiểu thực thể trong kag/schema/Legal.schema, gồm Article, ProhibitedAct, Sanction, Obligation, LegalTerm, Authority, RegulatedEntity, LegalDocument. Chưa có bước này thì extractor không dựng nổi prompt, vì prompt cần hỏi server xem có những kiểu gì.

../.venv/Scripts/knext.exe schema commit
Đúng thì thấy
Schema is successfully committed.

Soi lại trong Neo4j browser bằng CALL db.labels(), nhãn phải mang tiền tố Legal.

Bước 6 · Chạy thử đúng một văn bản có gọi mô hình

Chạy ở: kag/builder/. Vì sao: đây là lần đầu tiêu tiền. Lấy Nghị định 341/2026 về mật mã dân sự làm phép thử, vì nó là file xấu nhất kho — bảng to nhất, phình 1,95 lần, ba chunk 11.553 ký tự. Qua được nó thì 22 file kia gần như chắc chắn qua.

mkdir -p data/trial
cp data/processed/vn_an_ninh_mang/341-2026-ND-CP_mat-ma-dan-su.md data/trial/
cd kag/builder
../../.venv/Scripts/python.exe -c "
import os
from kag.common.registry import import_modules_from_path
import_modules_from_path(os.getcwd())
from indexer import buildKB
buildKB(os.path.abspath('../../data/trial'))
"
Đúng thì thấy
[Scanner]: There are total 1 data to process, worker 0/1 will process range [0, 1) 100%|██████████| 1/1 [04:12<00:00] Done process 1 records, with 1 successfully processed

Chạy lâu là bình thường, riêng file này khoảng 60 chunk, mỗi chunk ba lượt gọi mô hình.

Bước 7 · Kiểm hai thứ trước khi tiêu thêm tiền không gọi mô hình

Vì sao: đây là điểm quyết định. Sai ở đây mà cứ chạy tiếp 22 file nữa là mất tiền vô ích. Mở Neo4j browser rồi chạy hai truy vấn.

Kiểm một, tên thực thể còn dấu tiếng Việt không:

MATCH (n) WHERE n.name IS NOT NULL
RETURN labels(n)[0] AS nhan, n.name AS ten LIMIT 30
Đúng thì thấy
Nghị định 341/2026/NĐ-CP Điều 4. Nguyên tắc hoạt động mật mã dân sự Bộ Quốc phòng
Hỏng thì thấy
ngh nh 341 2026 n cp b qu c ph ng

Ra kiểu thứ hai nghĩa là bản vá giữ dấu trong kag/builder/__init__.py không chạy. Dừng lại, đừng index tiếp.

Kiểm hai, ba chunk bảng khổng lồ có ra thực thể tử tế không:

MATCH (n) WHERE n.content CONTAINS 'DANH MỤC SẢN PHẨM MẬT MÃ' RETURN count(n)

Vùng bảng không sinh ra thực thể nào thì chấp nhận được. Nhưng cả file chỉ ra dăm ba node thì mô hình đang nghẹn vì passage quá dài, lúc đó mới tính chuyện cắt nhỏ bảng.

Bước 8 · Index toàn bộ 23 văn bản có gọi mô hình

Chạy ở: kag/builder/. Vì sao: bước 7 xanh thì mới tới đây. 1.121 chunk, khoảng 3.363 lượt gọi mô hình. Chạy vài tiếng, cứ để máy chạy.

cd kag/builder
../../.venv/Scripts/python.exe indexer.py

KAG ghi điểm dừng vào kag/ckpt/. Lỡ tắt giữa chừng thì chạy lại lệnh cũ, nó bỏ qua phần đã xong. Ngược lại, sửa file .md thì phải xoá kag/ckpt/, không nó trả lại chunk cũ.

Bước 9 · Nạp metadata rồi hỏi thử không gọi mô hình

Chạy ở: kag/. Vì sao: bước này đưa ngày hiệu lực, trạng thái còn hay hết hiệu lực, và chuỗi thay thế giữa các văn bản vào đồ thị. Scanner chỉ nhận .md nên đây là đường duy nhất. Không tốn tiền gọi mô hình, chỉ tốn vector hoá.

cd kag
../.venv/Scripts/python.exe builder/metadata_to_graph.py
../.venv/Scripts/python.exe builder/injection.py
Đúng thì thấy
nodes: 70 (50 co metadata day du, 20 chi duoc dan chieu) edges: 62 [self-check ok] chuoi thay the 24/2018 -> 116/2025 dung chieu

Kiểm chuyện quan trọng nhất mà HybridRAG không làm được, là biết văn bản nào hết hiệu lực:

MATCH (a)-[:supersededBy]->(b) RETURN a.name, a.status, a.dateExpired, b.name

Rồi hỏi thật, sửa kag/solver/data/questions.json theo bộ câu hỏi của mình:

cd kag/solver
../../.venv/Scripts/python.exe eval.py
03

Theo dõi tiến độ khi đang chạy

Bước 6 và 8 chạy lâu, có bốn cách nhìn, từ thô tới tinh.

Nhìn ở đâuThấy gìCách xem
Thanh tiến độ trong terminal Số văn bản đã xong trên tổng, kèm thời gian còn lại ước tính Tự hiện, một dòng mỗi lần xong một file
Thư mục điểm dừng Số bản ghi đã xử lý ở từng khâu, đếm được ngay cả khi terminal bị che ls kag/ckpt/
Neo4j browser Số node tăng dần theo thời gian thực, đây là bằng chứng thật nhất MATCH (n) RETURN count(n), bấm chạy lại vài phút một lần
Log của server Lỗi phía server, ví dụ schema từ chối thuộc tính lạ docker logs -f release-openspg-server

Dòng tổng kết cuối cùng là thứ đáng tin nhất, ví dụ Done process 23 records, with 23 successfully processed. Hai số lệch nhau nghĩa là có file chết giữa chừng. Xem log tìm tên file, đừng cho rằng đồ thị đã đủ.

04

Sự cố hay gặp

Sáu triệu chứng đã gặp thật, kèm nguyên nhân thật bên dưới. Hai dòng đầu cùng một nguyên nhân, nên cách xử lý giống nhau.

Triệu chứngNguyên nhân thậtXử lý

KeyError: 'metadata_inject_chain' cũng là đứng sai thư mục nên config nạp ra rỗng cd kag rồi chạy lại

Sửa file .md rồi mà đồ thị không đổi KAG đọc lại từ điểm dừng cũ rm -rf kag/ckpt rồi index lại
Tên node mất hết dấu tiếng Việt bản vá trong kag/builder/__init__.py không được nạp dừng ngay, kiểm lại lệnh chạy có đi qua indexer.py không
Neo4j cứ khởi động lại không đủ RAM cho 4 GB heap hạ heap trong file compose xuống 2G
05

Khi muốn làm lại từ đầu

Xoá sạch đồ thị và dựng lại, giữ nguyên dữ liệu nguồn.

docker compose -f docker/docker-compose-west.yml down -v
rm -rf kag/ckpt

Rồi quay lại bước 1.

Cảnh báo

Cờ -v xoá luôn ổ đĩa của Neo4j và MySQL, tức là mất cả project id. Sau đó phải làm lại bước 4 và bước 5. Không có cờ đó thì đồ thị cũ vẫn còn.

Nguồn số liệu. Các con số 23 văn bản, 1.121 chunk và 3.363 lượt gọi mô hình là kết quả chạy thật scanner + reader + splitter của KAG 0.8.0 trên data/processed, chưa gọi mô hình và chưa ghi gì vào server. Thời gian chạy và chi phí là ước lượng, chưa đo thật. Lệnh và dấu hiệu trong chín bước đối chiếu với OpenSPG/KAG 0.8.0.
